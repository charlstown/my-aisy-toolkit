## Batch 1 — Resolve open installer mechanics (design)

- [x] @architect · Resolve one-liner syntax, bootstrap mechanism, and question wording; scaffold `setup-ai.md`: Close the three still-open DEFINITION GAP items from `requirements.md`. (a) Decide the literal one-liner text the user pastes in their terminal or asks their agent — per ADR-001 it must NOT be a bash/curl script, it must be a natural-language instruction the agent executes with its own fetch tool (e.g. "Fetch and follow the instructions at https://raw.githubusercontent.com/charlstown/my-aisy-toolkit/main/setup-ai.md"), usable both typed into a CLI agent invocation and asked conversationally, per FR-002. (b) Decide the bootstrap mechanism for each method: for the one-liner, the agent performs a GET on that URL to obtain `setup-ai.md`'s content; for copy-paste (FR-003), no fetch of `setup-ai.md` happens at all — the pasted block IS the full, self-contained instructions text, so `setup-ai.md` must read correctly standalone with no external "step 0" file. (c) Decide the exact wording of the profile-selection question (only asked when the fetched `catalog.yaml` declares more than one profile and none was specified, defaulting silently to `default` otherwise — FR-005) and the target-agent question (always asked explicitly, options "Claude Code" / "Codex CLI", never inferred from existing `.claude/`/`.codex/` folders — ADR-004/FR-004), matching the "direct, jargon-free, light tone" design principle from product-spec.md. Create `setup-ai.md` at the repo root with: a title, a "How to install" section containing the finalized one-liner text and the copy-paste block instructions, and empty step headings (Step 1..Step 5, see Batch 2) for subsequent tasks to fill in.

## Batch 2 — Author `setup-ai.md` instructions (FR-001…FR-016)

> **Batch 1 handoff**: `setup-ai.md` is scaffolded at the repo root with its title, the "How to install"

> step headings, each carrying an HTML-comment TODO listing the FRs it must cover. Fill the bodies in

> One ordering correction vs. the task titles below: **Step 1 asks the target agent only**; the profile
> question is defined in Step 1 but *fired* in Step 2, because whether to ask it depends on how many
> profiles the fetched catalog declares (FR-005 can't be evaluated before Step 2's fetch).

- [x] @code-developer · Write Step 1 — ask profile and target agent: In `setup-ai.md`, write the instructions telling the agent to always ask which target agent to install for (Claude Code or Codex CLI), explicitly and never inferred from folders already present (ADR-004, FR-004), and to ask which profile to install only when the catalog declares more than one and none was specified, defaulting to `default` otherwise (FR-005). Explicitly state the agent MUST NOT write any file until both questions are answered, and if the target-agent answer is missing/unclear it MUST ask again rather than guess (FR-014, edge case).
- [x] @code-developer · Write Step 2 — fetch and parse `catalog.yaml`: In `setup-ai.md`, instruct the agent to GET `https://raw.githubusercontent.com/charlstown/my-aisy-toolkit/main/catalog.yaml` (FR-006) and parse the resolved schema (`profiles.<profile>.commands: [...]` and `profiles.default.agents: [...]`, Claude Code source paths only, no per-agent destination paths — per requirements DEFINITION GAP note) to get the list of files to fetch for the chosen profile. Instruct that on 404 or unreachable, the agent MUST abort the whole installation, inform the user, and write nothing (FR-011).
- [x] @code-developer · Write Step 3 — fetch each skill/agent file: In `setup-ai.md`, instruct the agent to issue one GET per file declared in the catalog, against `.../main/ai-toolkit/default/commands|agents/*.md`, with no caching (FR-007). Instruct that on 404 or timeout for an individual file, the agent MUST retry once; if it still fails, inform the user and skip only that file, continuing with the rest of the profile (FR-012).
- [x] @code-developer · Write Step 4 — write files for the Claude Code target: In `setup-ai.md`, instruct the agent that when the target is Claude Code, it writes each fetched file unmodified into `.claude/commands/` or `.claude/agents/` in the target repo, matching the `ai-toolkit/default/` source byte-for-byte (FR-008). Instruct it to overwrite any existing file whose content differs from the source (FR-013) and add any new file not yet present (FR-015, re-install/update flow), and to make clear its side effects are limited to `.claude/`/`.codex/` only — never application code or other folders (FR-010).
- [x] @code-developer · Write Step 5 — translate and write for the Codex CLI target: In `setup-ai.md`, instruct the agent that when the target is Codex CLI, it translates each fetched Claude Code-format skill/agent into `.codex/skills/<name>/SKILL.md` format by its own interpretation at install time, with no pre-generated catalog or external translation service (ADR-002, FR-009). Apply the same overwrite/add semantics as Step 4. Include an inline note that Codex translation is best-effort and may be inconsistent, per the documented known risk in requirements' Edge Cases and tech-spec's Known Limitations.
- [x] @code-developer · Write the closing summary section: In `setup-ai.md`, instruct the agent to end every run by reporting, in plain language, which files were installed, which were updated (with reason: content changed), and which were skipped (with reason), mirroring the Logging table in tech-spec.md. No persistent log file is written — this is a conversational report only.
