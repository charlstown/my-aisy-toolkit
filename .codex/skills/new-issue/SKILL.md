# New GitHub issue

Use the user's language. Classify the request as a bug or feature; ask only when ambiguous. Do not write product code, refactor, or open a PR.

For a bug, inspect relevant code, reproduce safely when possible, and document expected versus actual behavior, steps, environment, evidence, scope, and suspected cause without overstating certainty. For a feature, ask up to three high-impact questions, then document problem, desired behavior, acceptance criteria, scope, and open decisions.

Use titles exactly as `[BUG] <title>` or `[FEAT] <title>`. Show the final issue title and body before creating it, then create it with GitHub only after the user confirms. Return the issue URL.
