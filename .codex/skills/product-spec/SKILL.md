# Product spec

Use the user's language. Read existing product, tech, and roadmap specs, README, and project manifest before interviewing the user about scope, user problem, decisions, style, exclusions, and discovery items. Ask only what the context cannot establish.

Write `specs/product-spec.md` in this order, omitting only genuinely inapplicable sections: Metadata, Vision, Problem Statement, Target User, Design Principles, Architecture, Interfaces, Configuration, Operations, Deliverables, Project Structure, Out of Scope, Future, Discovery. Extend rather than contradict established documentation. Mark unknowns clearly; do not invent technical versions or product decisions.
